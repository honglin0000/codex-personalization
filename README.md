# 我的 Codex 个性化｜GPT-6 Astra · Ultra

这是我自己在用的 Codex 个性化指令，完整原文放在 [AGENTS.md](AGENTS.md)。

**我使用的主模型是 GPT-6 Astra，思考强度是 Ultra（`ultra`）。搭配这套个性化，我自己的使用感受是：省了很多额度。**

这里分享我的实际设置和工作习惯。省额度是个人体验，尚未做定量对照；没有固定的节省比例，也不能据此认定 Ultra 本身更省额度。

| 设置 | 当前使用值 |
| --- | --- |
| 主模型 | **GPT-6 Astra**（`gpt-6-astra`） |

[config.example.toml](config.example.toml) 只包含这两项设置：

```toml

```

我希望在当前接口支持时，主代理与子代理都使用所选模型可用的最高思考强度：Astra、Terra、Sol 用 `ultra`，Luna 用 `max`。具体以实际可选的模型和档位为准，无法使用时要说明，不能假装已生效。

**`AGENTS.md` 记录工作偏好，模型与 Ultra 档位需要在实际界面或配置中设置。** 复制指令不会自动切换模型，也不会解锁账号没有的模型、工具或档位。

## 我在个性化里写了什么

- **把事情做完。** 以可用结果为目标，在授权范围内持续调查、实现、检查和修复，避免停在计划或初稿后反复问是否继续。
- **按任务读取资料和使用工具。** 能自行查明的信息先查；优先专用工具、连接器和 API，关键事实给依据。
- **有必要才分工。** 简单任务主代理直接做；能独立拆分、确实有助于质量或效率时再交给子代理。
- **验证与任务影响相称。** 必要检查通过就交付；有新改动、失败或未解决疑点时再扩大验证。
- **保留判断和授权边界。** 发现错误前提要指出；尚未授权的重要数据覆盖、对外发布、付款等操作先确认。
- **默认用简体中文。** 先讲结果，说明已完成、已尝试和未验证的部分。

我的默认模型分工如下，是个人使用习惯，可按任务调整：

| 模型 | 常用分工 | 指令中的思考强度偏好 |
| --- | --- | --- |
| Astra · `gpt-6-astra` | 复杂分析、方案取舍、疑难问题和关键复核 | `ultra` |
| Terra · `gpt-6.1-terra` | 电脑或浏览器操作及视觉理解 | `ultra` |
| Sol · `gpt-6.1-sol` | 实现、集成、排错和验证 | `ultra` |
| Luna · `gpt-6-luna` | 步骤明确、容易独立核验的轻量执行 | `max` |

主代理负责整合和最终验收。不要为了分工而重复执行，也不要仅为省额度自行降低思考强度。

## 怎么使用

1. 打开 [AGENTS.md](AGENTS.md)，先阅读，再按自己的习惯修改。浏览器偏好、模型分工和授权边界尤其需要按自己的环境决定。
2. 用作全局偏好时，把内容合并到 Codex 配置目录下的 `AGENTS.md`；默认位置是 `~/.codex/AGENTS.md`。已有文件先备份和合并。设置过 `CODEX_HOME` 时，使用该目录。
3. 只想用于一个项目时，把适用内容合并到该项目的 `AGENTS.md`。
4. 在模型选择器中选择 **GPT-6 Astra**，将思考强度设为 **Ultra**。用配置文件管理时，将示例中的两项合并到 `config.toml` 顶层，更新已有同名项，保留其他设置。
5. 开启新会话，检查界面中的模型与思考强度，再请 Codex 总结当前加载的个性化指令，核对是否符合预期。

全局和项目级 `AGENTS.md` 的加载方式见 [OpenAI 官方文档](https://learn.chatgpt.com/docs/agent-configuration/agents-md)。同一目录的 `AGENTS.override.md` 会优先于 `AGENTS.md`；项目内更具体的指令也可能改变最终行为。
